# Process overview

My first idea was simply a course that teaches Vue. In `IDEA.md`, I narrowed it to “Vue in the Wild” because a broad framework course could easily become twelve weeks of documentation summaries ([40feed1](https://github.com/comp4020-agentic-coding-studio/comp4020-ass2-u7663394/commit/40feed1)). I wanted students to understand how a small interface grows into an application that someone else can maintain. This gave me a way to direct the agent beyond asking for more content: each week needed a reason to exist and something students could build with it.

I chose Vue 2 → Vue 3 → Vue 3 + TypeScript so students could compare solutions to problems they already understood. Starting with Vue 2 makes sense as legacy maintenance, rather than advice for starting a new production system. The article reader introduces components, routing and shared state. The editorial dashboard revisits those responsibilities with modern Vue. The consultation app then adds typed data and more demanding failure cases. These are different applications, but the question of who owns the data connects them. TypeScript therefore has a purpose beyond learning another syntax.

I wanted these decisions to survive edits across many pages, so my instructions became course-specific rules in `CLAUDE.md` ([3b9859d](https://github.com/comp4020-agentic-coding-studio/comp4020-ass2-u7663394/commit/3b9859d)). They fix the three phases, require a distinct question and build for each week, and keep the second assessment in JavaScript. They also preserve SlopU branding and make the consultation project a simulation. This limits what the agent can invent while leaving room to improve explanations and examples.

Assessment readiness was especially important to me. Checking the sequence once would not protect it from later changes. The original assignment tests were already committed before implementation ([c8c610d](https://github.com/comp4020-agentic-coding-studio/comp4020-ass2-u7663394/commit/c8c610d)). The added `spec/` checks protect twelve dated weeks, the phase order, assessment weights totalling 100%, and linked decks. Readiness checks compare both lecture and studio dates with deadlines. An independent tool list prevents the agent from making a check pass by deleting a requirement. The same teaching information appears in assessment briefs, so students can use it too ([9ff9de8](https://github.com/comp4020-agentic-coding-studio/comp4020-ass2-u7663394/commit/9ff9de8)). The agent tested the checks with deliberate faults, including late teaching and missing deck links, and restored the output afterwards.

I deliberately left interest, voice and teaching coherence to human judgement. Different titles cannot prove that two weeks teach different things. My review instructions therefore asked for non-adjacent weeks and assessments to be read like a prospective student would. I also treated the website itself as evidence of the frontend care the course teaches.

The browser review shows why passing a build was not enough. At the two marking sizes, deeper slide inspection found an overflowing phone code block and a Next button that did not respond to Space. The fixes preserved readable code and native keyboard behaviour. Both lessons went back into `CLAUDE.md`, with screenshots and browser reports supporting the changes ([58687a8](https://github.com/comp4020-agentic-coding-studio/comp4020-ass2-u7663394/commit/58687a8)). The final local checks passed, including `pnpm check` and `pnpm check:evidence`. This gave me concrete evidence for assessing the agent’s output, while leaving the judgement of whether the whole semester feels worth taking to me.
