## The fault on the desk

The new service can hold paid: true and paymentFailed: true at once. Both are valid booleans. Neither explains what the interface should show. A larger domain needs a model with fewer contradictory states.

## Read this seam

```ts
type Payment =
  | { status: 'pending' }
  | { status: 'paid'; receiptId: string }
  | { status: 'failed'; reason: string }

function message(payment: Payment): string {
  if (payment.status === 'paid')
    return payment.receiptId
  return payment.status
}
```
